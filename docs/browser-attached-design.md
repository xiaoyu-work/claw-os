# Browser (attached) — design

Mode-B browser automation for Claw OS: drive the user's **running, logged-in**
Chromium tabs from the kernel, instead of spawning a separate headless
browser (the headless path is handled by `apps/web` + `cos-browser`).

## Why not just use Playwright / CDP?

| Need                                          | Playwright | This design |
|-----------------------------------------------|------------|-------------|
| Reuse user's cookies, SSO, MFA, password fills| ✗ (separate profile) | ✓ |
| Reuse extensions, ad blocker, custom CA       | ✗ | ✓ |
| Operate the window the user is actually looking at | ✗ | ✓ |
| Persistent ref tables across calls (per-tab)  | ✓ | ✓ |
| Cross-browser (Firefox, Edge, Brave)          | ✓ | Chromium now; Firefox packaging deferred |
| Headless throughput, isolated agent runs      | ✓ | use `apps/web` instead |

This design pays for the integration richness with extra moving parts (WebExt
+ Native Messaging host + AF_UNIX socket); `apps/web` (`cos-browser`) remains
the right tool for everything headless.

## Pipeline

```
┌────────────────────────────────────┐
│  user / agent issues:              │
│    cos app browser-attached <verb> │
└───────────────────────┬────────────┘
                        │  policy.require(...) [Python]
                        ▼
                  AF_UNIX socket
              $XDG_RUNTIME_DIR/claw-browser.sock
                        │
┌────────────────────────────────────┐
│ native_host.py                     │  spawned by Chromium when the
│   (apps/browser-attached/)         │  WebExtension calls connectNative
│   stdio  ◄────────────┐            │
└────────────────────────┴───────────┘
                        │
                        │  Chromium Native Messaging
                        │   (4-byte LE length + JSON, stdin/stdout)
                        ▼
┌────────────────────────────────────┐
│  extensions/claw-agent-browser     │
│    background.js  (service worker) │
│        ↕  chrome.tabs / scripting  │
│    content.js     (top frame only) │
└────────────────────────────────────┘
                        │
                        ▼
                  user's logged-in tabs
```

## Wire format (both NM and socket)

Identical JSON envelope on both legs:

```
request   { id: string, verb: string, args: object }
response  { id: string, ok: true,  result: object }
response  { id: string, ok: false, error: string }
```

The id is a UUID generated by the original caller (`main.py`), forwarded
verbatim, and used by `native_host.py` to route the matching response back
to the right socket connection.

## Verb & cap matrix

| verb              | cap (`core/src/caps/`)        | role gate (`role.rs`)          | scope     |
|-------------------|-------------------------------|--------------------------------|-----------|
| tabs.list         | `browser.tabs.read`           | connector / automator / admin  | wild      |
| tabs.activate     | `browser.tabs.read`           | connector / automator / admin  | wild      |
| nav.go            | `browser.nav` + `memory.write` | connector / automator / admin | host + app self-ref |
| dom.query         | `browser.dom.read`            | connector / automator / admin  | host      |
| page.snapshot     | `browser.dom.read`            | connector / automator / admin  | host      |
| page.screenshot   | `browser.dom.read` + `fs.write` | connector / automator / admin | host + path |
| dom.click         | `browser.dom.write`           | automator / admin              | host      |
| dom.fill          | `browser.dom.write`           | automator / admin              | host      |
| dom.fill_secret   | `browser.input.secret`        | admin                          | host      |
| eval (disabled)   | `browser.eval`                | admin                          | host      |

Read operations never serialize live values from input, textarea, select, or
contenteditable controls. `dom.query` and accessibility snapshots expose only
labels plus `value_present`; text snapshots replace populated editable regions
with a redaction marker. This protects custom controls even when heuristics do
not recognize their purpose.

Secret-field detection runs in `content.js` (`isSecretField`) and additionally
classifies password/hidden inputs, password/OTP/payment autocomplete tokens,
explicit private-data attributes, and credential-like id/name/ARIA/placeholder
metadata. Labels contribute to later accessible-name redaction but are not an
`isSecretField` input. `dom.fill` rejects those fields; only
`dom.fill_secret` (gated on `browser.input.secret`, admin-only) accepts them.

## File layout

```
core/src/caps/
  verb.rs          # adds browser.tabs.read, browser.nav,
                   #          browser.dom.read, browser.dom.write,
                   #          browser.input.secret, browser.eval
  catalog.rs       # per-verb UI metadata (icon, blurb, risk)
  role.rs          # rolls verbs into connector / automator / admin bundles

apps/browser-attached/
  app.json         # operations + needs (consent surface)
  main.py          # verb handlers, policy.require, socket client
  native_host.py   # NM stdio bridge ↔ AF_UNIX socket
  README.md

extensions/claw-agent-browser/
  manifest.json    # MV3, top-frame content_scripts: <all_urls>
  background.js    # SW, owns native port, dispatches verbs
  content.js       # top-frame DOM helper, secret-field detection
  popup.html       # tiny status / STOP UI
  popup.js
  README.md

tools/
  install-browser-agent.sh     # writes /etc/chromium/{policies,native-messaging-hosts}
```

## Install layout (run-time)

| Path | Contents |
|------|----------|
| `/usr/share/claw/extensions/claw-agent-browser/` | unpacked extension |
| `/etc/chromium/policies/managed/claw-agent.json` | force-install policy |
| `/etc/chromium/native-messaging-hosts/com.clawos.browser.json` | NM manifest pointing at the launcher |
| `/usr/lib/cos/claw-browser-host` | shim that `exec`s `python3 apps/browser-attached/native_host.py` |
| `$XDG_RUNTIME_DIR/claw-browser.sock` (mode 0600) | created by native host at startup |

## Trust model

1. **Chromium → native host**: the host's manifest lists the extension's ID
   in `allowed_origins`.  Chromium will only spawn the host when *that*
   extension calls `connectNative`.

2. **Native host → socket client**: the socket lives in `$XDG_RUNTIME_DIR`
   (`/run/user/$UID`), which is owned by the user and `chmod 0700`; the
   socket itself is `chmod 0600`.  Only processes running as the same UID
   can connect.

3. **Socket client → kernel**: `main.py` runs every verb through
   `policy.require()`, which uses the hidden policy bridge over `COS_SESSION`,
   inheriting the kernel's permission decision.

4. **Exact invoke gate**: each MCP call requires
   `agent.invoke:browser-attached/<tool>` and passes through the authenticated
   App Gateway before the target receives any authority
   (`core/src/agent/tools/app_gateway.rs`).

5. **Per-host scope**: most verbs require a host-scoped grant
   (`browser.nav:host=mail.example.com`), so a grant for one site does not
   unlock another.

6. **Secret floors**: secret-field fills are pinned to admin-role
   capabilities and always go through the approval queue. The `browser.eval`
   capability is also admin-only, but the current App request path does not
   supply the extension's `allow_eval` flag, so `eval` fails closed.

## Known MVP limitations

- **`eval` is not wired end to end**: `main.py` sends the expression but not
  the extension's required `allow_eval` flag. The extension therefore rejects
  every request. Keep the operation disabled until approval state is threaded
  through the socket/native-messaging request.

- **Session attachment for policy checks**: Chromium spawns the native
  host without `COS_SESSION` set; the Python verb handlers run inside the
  user's normal cos session (because `cos app browser-attached` is invoked
  by the agent).  No change needed there, but the *bridge itself* runs
  un-authenticated by design — that's why every caller must pass the verb
  through `main.py` rather than calling the socket directly.

- **MV3 service-worker lifecycle**: keeping the NM port open keeps the SW
  alive.  If Chromium ever evicts the SW anyway, the host process dies and
  the next CLI call returns "socket not found" until a wake event re-opens
  the port.  Acceptable for MVP.

- **Per-page ref freshness**: refs are stored in a `Map<id, WeakRef>` per
  content-script instance.  Navigation, page reload, and shadow-root
  re-render all invalidate refs.  Callers should re-`dom.query` rather than
  cache.

- **Cross-origin iframes**: DOM verbs are intentionally pinned to frame `0`,
  and the content script is installed only in the top document. This prevents
  a top-page host grant and a frame-local ref from acting on unrelated
  embedded origins. Refs also carry a random per-document nonce so a stale ref
  cannot collide with the same local sequence number after navigation.
  Supporting iframe automation requires explicit frame refs plus a separate
  capability check for each frame origin.

- **Firefox**: the current manifest and implementation are Chromium-specific
  (`chrome.*`). Firefox adaptation and signed XPI packaging are deferred.

- **Extension ID**: the install script currently leaves
  `allowed_origins` empty.  After loading the extension unpacked once,
  re-run the installer with `CLAW_EXT_ID=<id>` so Chromium can match it
  against the NM manifest.
